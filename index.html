THE PROBLEM

Robotics AI is being built on rented ground.

Proprietary lock-in
Every hardware vendor ships a closed stack. Switch robots and you rewrite your entire software layer.
Cloud dependency
Cloud-dependent foundation-model workflows can be unavailable in denied, contested, or air-gapped environments.
No shared platform
Integrators repeatedly rebuild the same capabilities instead of reusing a shared layer across platforms.
This slows adoption in defense, industrial, and sovereign environments.
THE SOLUTION

ORYX — the operating layer for physical AI.

New hardware means a new driver. No change to the reasoning layer, the API, or existing use cases.

Prompt
Developer describes the mission in natural language.
Reasoning layer
Local or external LLM / VLM builds context and decision logic.
Control API
Unified command layer — one interface for every robot.
Hardware drivers
Per-model brokers translate commands into native robot actions.
SOVEREIGN BY DESIGN

Zero cloud dependency, by default.

Fully on-premise / air-gapped
LLM and VLM inference run locally on open models — no external API calls required to operate.
Cloud-agnostic by design
Deploy on any cloud, a private data center, or entirely offline — no dependency on any single provider.
Data stays inside the perimeter
In on-prem deployments, mission data, context, and reasoning remain inside the customer's environment.
Built for disconnected operations
Designed to support operation when commercial cloud connectivity is unavailable or cannot be guaranteed.
